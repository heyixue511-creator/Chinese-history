# Dimension Registry — 维度体系成长注册表

本文件定义当前垂直领域的 Level 2 维度注册规则。它不把 5 个维度固定为永久结构，而是把它们视为**首批摄入阶段的试运行分析轴**。

## 一、设计原则

1. **初始假设，不是最终分类**：A–E 依据现有 24 册书目结构提出，状态为 `pilot`；必须由首批知识元检验，不得因为写进注册表就当作既成事实。
2. **维度从知识中涌现**：新增维度必须来自无法归类的知识元、跨维度主题或反复出现的研究问题。
3. **先 Topic、再 Theme、后 Dimension**：具体问题能作为既有 Theme 下的 Topic 时不新增 Theme；能作为 Level 3 Theme 表达时不新增 Level 2。
4. **维度必须有组织能力**：一个 Level 2 维度至少能稳定组织 2 个 Level 3 Theme，每个 Theme 继续组织可操作 Topic。
5. **演化必须可追溯**：新增、拆分、合并、弃用维度都必须保留旧编号与迁移说明。

### 维度边界说明

- **A** 处理“如何写设计史”：包括通史分期、核心概念、史学方法、设计史与工艺美术史/艺术史的关系。它不是“设计思想史”本身；具体观念应落到 B–E 的 Topic 或 KU。
- **B** 处理“物如何被做出来”：材料、工艺、工具、生产组织、技术条件。它不自动吞并商业流通或视觉传播。
- **C** 处理“视觉与文字如何被组织”：汉字设计、字体、排版、印刷、书籍装帧、广告、海报、标志与信息图形。
- **D** 处理“设计如何被组织起来”：学校、出版社、商会、工厂、展览、政策、职业群体与设计教育。
- **E** 处理“中国设计如何与现代性和外部世界发生关系”：冲击—回应、本土化、跨国流通、技术转移、身份建构。它不替代 B/C/D 的具体机制分析。

> 一个 KU 可以同时属于多个维度，但必须有 `primary_dimension`；跨维度关系不能靠“看起来像”推定。

## 三、维度生命周期

| 状态 | 含义 | 允许操作 |
|---|---|---|
| `core` | 稳定核心维度 | 正常承载 Theme、Topic 与知识元 |
| `proposed` | 候选维度 | 记录观察，不修改正式 hierarchy |
| `pilot` | 试运行维度 | 可建立临时映射和样本 Theme/Topic |
| `core_candidate` | 准备晋升 | 需通过 evolve-hierarchy、system-review、evidence/boundary/hierarchy impact 审查 |
| `split_candidate` | 准备拆分 | 需定义拆分边界和迁移影响 |
| `merge_candidate` | 准备合并 | 需说明重叠原因与旧编号映射 |
| `deprecated` | 不再扩展 | 保留历史链接，不再新增 Theme/Topic |

## 四、新维度候选条件

候选维度必须同时满足：

1. 至少 5 个知识元无法自然归入现有维度，或至少 2 个成熟 Theme 长期横跨多个维度且无法被现有维度解释。
2. 该候选不是新增 Topic 或 Theme 即可解决的问题。
3. 候选维度有独立核心问题，且与既有维度互不重叠。
4. 至少能组织 2 个 Level 3 Theme。
5. 每个候选 Theme 至少包含可操作 Topic，并具备理论、实证与文献支撑。
6. 有完整迁移计划：编号、链接、主题归属、索引、历史版本。

## 五、复审触发条件

满足以下任一条件时，必须复审 A–E：

- 已完成 3 册书的摄入，且累计不少于 100 个 KU；
- 出现至少 5 个无法自然归入 A–E 的 KU；
- 同一批 KU 在三个以上维度间反复摇摆，无法稳定选择 `primary_dimension`；
- 某一维度长期没有 Theme/Topic 支撑，或与另一维度边界持续重叠。

复审结果写入本文件“变更记录”，并通过 `evolve-hierarchy` 留下 evidence、boundary test、hierarchy impact 与 unresolved items。

## 六、当前观察

- 现有书目明显覆盖 A–E 五个方向：通史与史论（A）、工艺美术与造物（B）、汉字/字体/平面设计（C）、设计教育与商业美术（D）、现代设计与跨文化（E）。
- 但“商业美术”“书籍装帧”“文字设计”可能同时落入 C 与 D，需在首批摄入后观察是否应拆分或调整边界。
- 相邻领域的“美术教育”“机械史”“美学文库”暂不单列维度；它们先作为 A/B/D/E 的上下文来源。
