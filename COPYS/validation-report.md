## 测试的移植依赖

首次直接在空副本执行原测试得到 245 passed、16 subtests passed、5 failed。失败均来自测试直接依赖原项目的具名 Theme/Topic 文件或现成层级挂载，而这些研究数据不应进入新项目。

已新增 `portable/run_tests.py`，在系统临时目录中复制工作流，建立 4 个只含类型/代码的合成结构节点和 1 个合成 KU，然后执行全部原测试。它不修改原脚本、不修改测试断言、不跳过失败测试、不 mock 被测函数，也不向正式知识目录写入样本。测试后临时目录自动清理。

- 首次发现证据：`all_copied_tests.log`。
- 修复移植测试依赖后的证据：`all_copied_tests_with_isolated_fixtures.log`。
- 完整命令与退出码：`validation-report.json`。

## 实际限制

- 领域配置、八类对象、五级层级及部分测试仍具有源项目假设；原样保留以忠实复刻，尚未为其他领域重新设计。
- Codex Hook 使用 POSIX/Linux 命令，Claude 入口目前是符号链接文本占位；目标环境需要恢复/适配，并独立确认客户端加载和信任。
- 未进行联网 collector 验证，未验证目标机器上的浏览器交互或客户端硬门禁。
- 展示代码和静态图像保留原项目品牌与三书文案，图谱数据为空；迁移前必须更新文案，旧二维数据和旧哈希清单没有移植。
- 没有复制源项目健康、评测验收、历史例外基线或迁移映射；未在空模板上伪造这些状态。
- 没有执行需要独立 Git 根、实际知识数据与派生基线的整仓发布 closure，也未对源项目提交或推送。

原配置和代码的保留不等于认证其在任意领域即插即用。移植方法见 `reuse-guide.md`。
